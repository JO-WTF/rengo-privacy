Galplay 隐私政策

最后更新：2026 年 11 月 23 日

概述

Galplay 是在 iPhone 和 iPad 上运行用户自行导入的 Ren'Py、Kirikiri、ONScripter 等引擎视觉小说的播放器。应用不要求账号，没有广告、第三方分析或追踪 SDK； 不会把完整游戏文件上传到 Galplay 的服务器。为提供试用和购买功能，App 会 自动与 Galplay 权益服务同步第 7 节所述的 Apple 交易信息；查询公告时会附带第 2 节所述的 App 与设备信息；游玩时会发送第 8 节所述的启动统计（游戏标题、引擎、游玩时长）。第 6 节说明你主动提交的适配需求，以及经本次确认或持续授权发送的异常诊断、相关日志和对应游戏的可用存档副本。

留在你设备上的数据

以下内容保存在 App 沙盒或你明确选择的外部文件夹中；除第 6 节所述、经你确认或 持续授权发送的游戏名称、诊断内容和对应游戏存档副本，以及第 8 节所述的游戏标题与 游玩时长外，Galplay 不会把它们上传到自有服务器。你主动使用备份或传输时，文件会送往 你选择的位置：

  • 你导入的作品文件
  • 游戏存档与游戏内设置
  • 游戏库信息（标题、封面、游玩记录）
  • App 偏好设置
  • 在设备上生成的翻译内容

删除 App 会删除其沙盒内的数据；外部文件夹中的文件由你自行管理。

联网行为

导入的游戏可能按其自身设计联网。

Galplay 仅在下列功能中联网；公告列表、游戏适配表和权益状态（第 7 节）会在打开 App 时自动更新，启动统计（第 8 节）在游玩时自动发送。开启第 6 节的自动上报授权后， 本功能支持的异常或崩溃诊断及可用存档副本会在后台发送；其他传输、查询与提交由你选择使用。

1. 作品资料与封面查询

当你为作品匹配资料时，App 会向以下服务发送你查询的作品名称：

服务 用途
VNDB (api.vndb.org) 视觉小说资料
IGDB (api.igdb.com)，经 Twitch 授权 (id.twitch.tv) 游戏资料
SteamGridDB (steamgriddb.com) 封面图片

查询会向相应服务发送作品名称。这些服务有各自的隐私政策，不受我们控制。

2. 公告与点赞

打开 App 后可能从 Galplay 公告服务获取公告，使用 App 当前语言；你点赞时会提交公告编号，不要求账号。已点赞记录只保存在本机，不跨设备同步。

若 App 已从权益服务取得你的 Galplay ID（GP ID，见第 7 节），查询公告时会同时查询发给你的个人消息（例如客服补偿的游玩时间），并附带 GP ID、App 版本、系统版本、设备型号（例如 iPhone17,2）、App Store 地区和 App 语言。服务器为该 GP ID 保存最近一次查询的时间和这些信息，用于客服支持和兼容问题排查；不发送设备标识符或广告标识符。

3. WebDAV 存档备份（可选）

若你自行配置了 WebDAV 服务器，App 会把存档文件上传到你指定的服务器。服务器地址、用户名与密码保存在你设备的系统钥匙串／偏好存储中，不会发送给我们或任何第三方。数据流向完全由你决定。

4. 局域网游戏与存档传输（可选）

启用后，App 会在你的设备上开启一个临时的本地 HTTP 服务，供同一局域网内的浏览器传入游戏或存档文件。关闭传输页面后服务停止，文件不会经此功能上传到 Galplay 的服务器。

5. 外部文件夹备份（可选）

若你通过「文件」选择了一个外部文件夹作为备份位置，存档会写入该文件夹。 Galplay 仅在你明确配置、备份、浏览、恢复或删除时访问该文件夹；若文件夹位于 iCloud Drive，后续同步由 iOS 管理。WebDAV 和网盘游戏导入仍在开发中，与现有的 WebDAV 存档备份不同。

6. 游戏适配请求与异常诊断报告（可选）

App 会从 Galplay 自己的服务（api.galplay.cn 或 galplay.fuckk.me，视你的地区而定） 获取游戏适配表。适配需求与诊断按以下方式提交：

手动提交适配需求。 你在「提交适配需求」中提交时，App 发送你填写的游戏名称、平台和备注。

异常与崩溃诊断。 本功能支持游戏启动失败、运行异常和 App 崩溃等情况，不限于存档错误。 默认由你在提示中点「确定」后，在后台发送本次诊断及对应游戏的可用存档副本。 「不再询问」默认勾选；保持勾选并点「确定」，才会授权以后对本功能支持的异常或崩溃， 自动在后台发送诊断、相关日志和对应游戏的可用存档副本。你可以手动取消勾选，再点「确定」 仅发送本次资料。勾选状态本身不会建立授权；点「取消」或关闭提示，不会授予持续授权， 也不会启动本次发送。

你可以在 App 设置中关闭以后的自动上报。关闭不会撤回已经确认并进入发送队列的报告及附件， 这些项目仍会继续发送或按既有规则重试。该授权使用独立设置，不会从旧的同意设置继承开启状态。

游戏关联报告会按实际可获取的信息包含：

  • 游戏名称（含文件路径的名称不会发送）；
  • App 在本机为该游戏生成的随机编号，以及本次失败和本次启动的随机编号；
  • 所用引擎与运行时版本，失败阶段、原因和错误代码；
  • App 版本与构建号、系统版本和设备型号（不含设备唯一标识）；
  • 文本诊断报告，包含本次运行概况及截至出错时近期的运行日志，例如出错的组件、资源或脚本位置名称、行号、错误代码和失败摘要。

文本诊断可包含少量最近显示的剧情文本（可能含你设置的游戏内名称）、失败前的关键操作及 当时的游戏进度信息，以帮助定位问题；不包含整份游戏脚本、游戏文件或键盘输入流。 文本报告发送前沿用现有的敏感信息过滤，必要的游戏内相对资源名称可能保留。 报告不包含设备标识符或广告标识符。相关运行日志有大小限制；报告在后台发送，网络不可用时 会在本机暂存已获准发送的内容并稍后重试，重试次数有上限。

存档副本。 对于能可靠关联到游戏的报告，App 会尝试将该游戏的可用存档副本打包为 .galsave 附件。App 使用稳定的存档快照，或在可安全读取时复制已有存档，不要求引擎额外保存， 也不改动原存档。采集时间可能晚于故障发生时间，附件不保证包含尚未完成写入的最新进度。 原生存档副本可能包含游戏内名称、游戏内设置及游戏保存的其他内容；它不会按文本日志的规则过滤。 附件通过同一需求记录的既有消息附件通道上传，沿用单个附件 16 MiB 的大小上限， 不引入新的第三方 SDK。没有可用包、来源暂忙、包过大或无法确认关联等情况，会记录未附带存档的原因； 不会以其他游戏或后续新会话的存档代替。

Apple MetricKit 提供的系统崩溃证据若不能可靠关联到某个游戏，只发送系统诊断，并将存档状态 标为「无对应游戏」；不会使用最近游玩的游戏来推断或补充存档。

若 App 已从权益服务取得你的 Galplay ID（GP ID，见第 7 节），适配需求和诊断报告会附带 它，以便你联系我们时找到对应记录；这些记录因此与你的 GP ID 关联。

提交后，App 会用服务器返回的请求编号查询处理状态和开发者回复；「我的需求」列表只保存 在本机。

用途。这些信息只用于排查兼容问题、为游戏增加支持和回复你的请求；不用于广告或追踪，不出售。服务运行在阿里云（中国大陆，深圳）的服务器上，适配需求、诊断报告及其索引、权益记录和启动记录存储在该服务器上，服务器数据的异地备份存放在 Cloudflare 的私有 R2 中。海外地区的请求会先经过 Cloudflare 转发到该服务器，Cloudflare 会处理你的 IP 地址等连接信息以传输请求；除阿里云、Cloudflare 作为托管与传输服务商外，不与第三方共享。Galplay 的数据库不保存 IP 地址。

保留与删除。适配需求和诊断索引保存在服务器上，在删除前会一直保留。如需删除，请发邮件到下方联系地址，写明游戏名称和提交时间（可在「我的需求」中查看）；如有 GP ID 也请一并提供。新版压缩报告保留 180 天后删除；需求记录、索引和旧版报告不因此自动删除。我们会删除对应的需求及其诊断报告。

7. 试用、购买与 Galplay ID

Galplay 提供 7 天免费试用和 App 内购买（限时通行证与永久解锁）。购买和付款由 Apple 通过 App Store 处理；Galplay 不会收到你的 Apple 账户名称、邮箱或付款信息。

为确认你的使用权益，App 在打开或回到前台、启动游戏、购买和恢复购买时，会把以下信息发送到 Galplay 权益服务（pay.galplay.cn 或 galplay-pay.fuckk.me，视你的地区而定）：

  • Apple 签名的 App 交易信息：包括此 App 在你 Apple 账户下的交易编号（App Transaction ID）、首次获取日期与版本，以及正式／沙盒环境；
  • Apple 签名的 App 内购交易：商品 ID、交易编号、购买日期，以及退款或撤销日期；
  • 试用开始记录：首次累计在前台游玩满 60 秒时，App 发送一个随机事件编号、服务器此前签发的时间凭证和经过的时长，用来确定 7 天试用从何时开始；不发送游戏名称或游戏内容；
  • 购买前的权益状态：购买时（包括限时通行证和永久解锁），附带服务器此前签发的权益状态，用于记录购买前剩余的时长。

权益服务会通过 Apple 的 App Store Server API 核对这些交易并读取本 App 的购买历史，也会接收 Apple 发送的购买、退款和撤销通知。服务器保存：App Transaction ID、GP ID、试用开始时间及其凭证、本 App 的购买记录（交易编号、商品、购买日期、退款／撤销日期、购买前剩余时长）、早期付费版的购买资格（首次购买日期与版本）、Apple 通知记录，以及客服调整记录（例如补偿时长或永久权益，包括操作原因）。App 中的退款提醒由这些记录生成。

Galplay ID（GP ID）。首次同步时，服务器根据 App Transaction ID 生成一个以 GP- 开头的短编号，显示在 App 中，供你联系我们时提供。它也会附在你之后提交的适配需求和失败诊断报告中（见第 6 节）。

用途。这些信息只用于验证和恢复你的权益、处理退款以及客服支持；不用于广告或追踪，不出售。服务运行在阿里云（中国大陆，深圳）的服务器上，适配需求、诊断报告及其索引、权益记录和启动记录存储在该服务器上，服务器数据的异地备份存放在 Cloudflare 的私有 R2 中。海外地区的请求会先经过 Cloudflare 转发到该服务器，Cloudflare 会处理你的 IP 地址等连接信息以传输请求；除阿里云、Cloudflare 作为托管与传输服务商，以及向 Apple 核对交易外，不与第三方共享。Galplay 的数据库不保存 IP 地址。

保留与删除。权益记录目前没有自动删除期限；为了让你能随时恢复已购权益，会一直保存。如需删除，请发邮件到下方联系地址并提供你的 GP ID，我们会手动删除服务器上对应的记录。删除后，试用和客服调整记录无法恢复；在 Apple 完成的购买仍可通过「恢复购买」重新向 Apple 核对。

8. 启动统计

若 App 已取得你的 Galplay ID（见第 7 节），每次游戏成功启动（显示出第一个画面）时，App 会向 Galplay 公告服务（api.galplay.cn 或 galplay.fuckk.me，视你的地区而定）发送：

  • 本次启动的随机编号和你的 GP ID；
  • 游戏引擎类型（例如 Kirikiri、Ren'Py）、游戏在游戏库中的完整标题（超过 120 个字符时只取前 120 个），以及 App 版本。

游戏切到后台或结束时，App 再用同一编号发送本次启动在前台游玩的时长。没有 GP ID 时不发送；网络不可用时，App 会在本机暂存这些记录（最多 100 条）并稍后重试。不发送游戏文件、存档、游戏文本、文件路径、设备标识符或广告标识符。App 内没有关闭启动统计的开关。

服务器保存每次启动的记录（引擎、标题、App 版本、开始时间、游玩时长），以及每个 GP ID 的启动次数、最近启动时间和累计游玩时长。

用途。了解各引擎和游戏的实际使用情况，用来安排兼容与优化的优先级；不用于广告或追踪，不出售。服务运行在阿里云（中国大陆，深圳）的服务器上，适配需求、诊断报告及其索引、权益记录和启动记录存储在该服务器上，服务器数据的异地备份存放在 Cloudflare 的私有 R2 中。海外地区的请求会先经过 Cloudflare 转发到该服务器，Cloudflare 会处理你的 IP 地址等连接信息以传输请求；除阿里云、Cloudflare 作为托管与传输服务商外，不与第三方共享。Galplay 的数据库不保存 IP 地址。

保留与删除。每次启动的记录保存 3 年，到期自动删除。每个 GP ID 的启动次数、最近启动时间和累计游玩时长是不含游戏标题的汇总，与第 7 节的权益记录一同保存。如需提前删除，请发邮件到下方联系地址并提供你的 GP ID，我们会删除对应的启动记录和汇总。

你导入的内容

除内置示例作品外，Galplay 不提供或分发第三方游戏。你导入的作品由你自行获取，其内容与合规性由你负责。App 会在设备本地检查项目结构与运行所需资源，不会把完整游戏文件上传到 Galplay 的服务器。

儿童

Galplay 当前在 App Store 的年龄分级为 4+，应用本身不包含成人游戏内容，也不要求创建账号。用户自行导入的第三方作品可能有不同的适龄要求；家长应根据具体作品判断。

Galplay Privacy Policy

Last updated: November 23, 2026

Overview

Galplay plays visual novels that you import on your iPhone or iPad, using Ren'Py, Kirikiri, ONScripter, and other engines. The app requires no account and has no ads or third-party analytics or tracking SDKs. It does not upload complete game files to Galplay's servers. To provide the trial and purchases, the app automatically syncs the Apple transaction information described in section 7 with Galplay's entitlement service. It sends the app and device information described in section 2 with announcement checks, and the launch statistics described in section 8 (game title, engine, play time) while you play. Section 6 explains compatibility requests you submit and diagnostic reports, related logs, and available copies of the associated game's saves sent with your confirmation or ongoing permission.

Data that stays on your device

Imported works, saves and in-game settings, library information, preferences, and translations generated on your device stay in the app sandbox or an external folder you explicitly choose. Exceptions are the game name, diagnostic content, and associated game save copies sent with your confirmation or ongoing permission under section 6, and the game titles and play time described in section 8. Otherwise, Galplay does not upload them to its own servers. User-selected backups and transfers may send files to the destination you choose. Deleting the app removes sandbox data; you manage files in external folders yourself.

Network activity

Imported games may connect to the internet according to their own design.

Galplay uses the network only for the functions below. The announcement list, the game compatibility list, and your entitlement status (section 7) refresh when the app opens, and launch statistics (section 8) are sent while you play. If you enable automatic reporting under section 6, supported error or crash reports and available save copies are sent in the background. Other lookups, transfers, and submissions are used at your choice.

1. Metadata and cover art lookups. When you match a work, the app sends the title you are searching for to VNDB (api.vndb.org), IGDB (api.igdb.com, authenticated via id.twitch.tv), and SteamGridDB (steamgriddb.com). The title is sent to the relevant service. These services have their own privacy policies, outside our control.

2. Announcements and likes. The app may request announcements in your app language when it opens. Liking an announcement sends its ID without requiring an account; the liked state stays on this device and does not sync across devices. Once the app has your Galplay ID (GP ID, see section 7), the same check also fetches personal messages for you (such as play time added by support) and includes your GP ID, app version, system version, device model (for example iPhone17,2), App Store country, and app language. The server keeps the time of the latest check and this information for that GP ID for support and compatibility troubleshooting. No device or advertising identifier is sent.

3. WebDAV save backup (optional). If you configure a WebDAV server, save files are uploaded to the server you specify. The address, username, and password are stored on your device and are never sent to us or any third party.

4. Local network game and save transfer (optional). When enabled, the app runs a temporary local HTTP service so a browser on the same network can send game or save files. The service stops when you close the transfer page; this feature does not upload the files to Galplay's servers.

5. External-folder backup (optional). If you pick a folder in Files, saves are written there. Galplay accesses it only when you explicitly configure, back up, browse, restore, or delete. If you choose iCloud Drive, iOS handles subsequent syncing. WebDAV and cloud game import are still in development; this is separate from the available WebDAV save backup feature.

6. Compatibility requests and diagnostic reports (optional). The app loads the game compatibility list from Galplay's own service (api.galplay.cn or galplay.fuckk.me, depending on your region). Requests and diagnostics are submitted as follows:

Compatibility requests you submit. When you submit Request compatibility, the app sends the game name, platform, and note you entered.

Error and crash reports. This feature supports game launch failures, runtime errors, and app crashes, including cases unrelated to saving. By default, tapping OK in the prompt authorizes the current report and available copies of the associated game's saves to be sent in the background. Don't ask again is checked by default. Leaving it checked and tapping OK grants ongoing permission to send future errors or crashes supported by this feature, together with diagnostic information, related logs, and available copies of the associated game's saves, automatically in the background. If you clear the checkbox before tapping OK, only the current report and any available save copy are sent. The checked state alone does not grant ongoing permission. Tapping Cancel or closing the prompt does not grant ongoing permission or start that submission.

You can turn off future automatic reporting in the app's settings. Doing so does not withdraw reports or attachments already authorized and queued; those items continue to send or retry under the existing rules. This permission has its own setting and does not inherit an enabled state from older consent settings.

Reports associated with a game include the following information when available:

  • The game name (a name containing a file path is not sent);
  • Random IDs the app created on your device for the game, this failure, and this launch;
  • The engine and runtime version, failure phase, reason, and error codes;
  • The app version and build number, OS version, and device model (not a unique device ID);
  • A text diagnostic report with the run overview and recent logs at the failure, including component or resource names, script locations, line numbers, error codes, and failure summaries.

Text diagnostics may include a small amount of recently shown story text (which may contain in-game names you set), key actions before the failure, and game progress information at that time to help locate the problem. They do not include the complete game script, game files, or keyboard input streams. Text reports use the existing sensitive-information filtering before transmission; necessary relative resource names inside the game may remain. Reports do not include device or advertising identifiers. Related run logs have size limits. Reports are sent in the background; if the network is unavailable, authorized content is kept on the device for later retries, up to a limited number of attempts.

Save copies. For reports reliably associated with a game, the app attempts to package available copies of that game's saves as a .galsave attachment. It uses a stable save snapshot or copies existing saves when they can be read safely. It does not ask the engine to save again or change the original saves. Collection may happen after the failure, so the attachment may not contain the latest progress from an unfinished write. Native save copies may contain in-game names, in-game settings, and other content stored by the game; they are not filtered under the text-log rules. The attachment uses the existing message attachment channel for the same request, with the existing 16 MiB limit per attachment and no new third-party SDK. If no package is available, the source is busy, the package is too large, or the association cannot be confirmed, the reason for omitting the save is recorded. Saves from another game or a later session are not used as substitutes.

8. Launch statistics. Once the app has your Galplay ID (see section 7), each time a game launches successfully (shows its first frame), the app sends to the Galplay announcement service (api.galplay.cn or galplay.fuckk.me, depending on your region) a random ID for this launch, your GP ID, the game engine (for example Kirikiri or Ren'Py), the game's full title in your library (only the first 120 characters if longer), and the app version. When the game goes to the background or ends, the app sends the foreground play time of that launch under the same ID. Nothing is sent without a GP ID; when the network is unavailable, the app keeps these records on the device (at most 100) and retries later. No game files, saves, game text, file paths, or device or advertising identifiers are sent. The app has no switch to turn launch statistics off. The server stores each launch (engine, title, app version, start time, play time) and, for each GP ID, the number of launches, the latest launch time, and the total play time.
